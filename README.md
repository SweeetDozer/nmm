# MusicOrder 0.2

Настольное приложение на C++20, Qt 6 и TagLib для локальной музыкальной коллекции. Первая сборка — Fedora KDE. Это приложение с настоящим чтением и записью файлов, а не веб-макет.

## Сборка и запуск на Fedora

Нужны Qt ≥ 6.4 и TagLib ≥ 2.0 (API сложных полей для обложек).

```bash
sudo dnf install gcc-c++ cmake ninja-build qt6-qtbase-devel qt6-qtmultimedia-devel taglib-devel
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=OFF
cmake --build build -j 4
./build/musicorder
```

Проверено на Fedora 44, Qt 6.11.2, TagLib 2.3. Воспроизведение использует Qt Multimedia и системный мультимедийный backend; ошибки недоступных кодеков выводятся в журнал. Само приложение FFmpeg для чтения/записи тегов не запускает.

Дополнительная локальная установка:

```bash
cmake --install build --prefix "$HOME/.local"
```

## Работа с коллекцией

1. **Открыть папку** — рекурсивно прочитать MP3, FLAC, OGG Vorbis. Символические ссылки пропускаются. Таблица заполняется пакетами в фоне; сканирование можно отменить. Ошибки отдельных файлов выводятся в журнал и фильтруются отдельно.
2. Поиск охватывает теги, имена и пути. Сортировка доступна по заголовкам. Фильтры: неполные теги, ошибки, формат. Выделение нескольких строк — Ctrl / Shift; Ctrl+A выбирает все видимые строки.
3. Двойной щелчок или **Редактор** — основные поля, все текстовые поля, обложка и прослушивание. Из нескольких выделенных файлов открывается первый. Кнопка «Сохранить» открывает предпросмотр, а не пишет сразу.
4. **Из имён файлов** — предложить название по имени файла и исполнителя по непосредственной родительской папке. Это непроверенная подсказка, особенно если папка является альбомом. Исходные пути не меняются. Пометки remix/live/cover сохраняются; удаляется только часть очевидного поискового мусора.
5. **MusicBrainz** — поиск для выделенных файлов. Все записи показываются с причинами и источником. Выберите запись, затем при желании конкретное издание. Можно продолжить только с названием и исполнителем, пропустить файл или завершить поиск с уже собранными предложениями.
6. В предпросмотре **все флажки первоначально сняты**. Можно выбрать отдельные поля, все показанные изменения или только пустые поля. Затем показывается итоговый список; запись начинается только после второго подтверждения. Отмена фоновой записи останавливает пачку между файлами, уже записанные файлы остаются сохранёнными.
7. **Повторы** проверяет всю загруженную коллекцию. Точные копии: одинаковый размер и SHA-256 полного файла. Возможные повторы: совпадающие нормализованные исполнитель + название либо имя файла и близкая длительность (до 2 секунд). Разные версии записи могут попасть в эту группу: это не доказательство идентичности звука. Двойной щелчок по варианту включает прослушивание. Качество видно по формату, битрейту, частоте и числу каналов.
8. Для переноса нужно явно отметить лишние файлы и подтвердить список. Пересекающиеся группы проверяются вместе: хотя бы один вариант в каждой группе должен остаться. Автоматического удаления нет.

Альбом, дата, номер трека и обложка не выдумываются: они предлагаются только после явного выбора издания. Надёжное предложение требует совпадения названия и исполнителя, известной длительности с отклонением не более 2 секунд и отсутствия выявленного конфликта версии. Несколько подходящих результатов считаются неоднозначностью. Даже надёжное предложение само по себе ничего не записывает.

## Резервные копии и восстановление

Перед каждым сохранением создаётся полная копия файла, проверяется её SHA-256 и записывается `restore.json` с исходным путём. После сохранения файл открывается заново: выбранные значения, изменённая обложка и остальные текстовые поля проверяются. Ошибка одного файла не останавливает пачку. Если файл изменился после предпросмотра, запись отклоняется. При ошибке проверки копия остаётся доступной; автоматического восстановления нет.

Каталог данных определяется `QStandardPaths::AppDataLocation`. Обычно на Fedora:

```text
~/.local/share/MusicOrder/MusicOrder/
  backups/<uuid>/<исходное имя>
  backups/<uuid>/restore.json
  quarantine/<uuid>/<исходное имя>
  quarantine/<uuid>/restore.json
```

Фактический путь виден в итоговом подтверждении и журнале; кнопка **Копии и восстановление** открывает его в файловом менеджере. Каталог данных приложения исключён из сканирования. Копии не очищаются автоматически: для больших пачек требуется место под полные оригиналы.

«Перенос» в `quarantine` сначала копирует файл, проверяет хеши копии и исходника, сохраняет журнал, затем удаляет исходник. Неудачная проверка оставляет исходник на месте.

Восстановление (Python ≥ 3.11):

```bash
# Если исходного файла уже нет, например после переноса:
python3 scripts/restore.py '/полный/путь/к/restore.json'

# Откат изменённых тегов, когда исходный путь занят:
python3 scripts/restore.py '/полный/путь/к/restore.json' --replace
```

Скрипт проверяет SHA-256 копии. С `--replace` он предварительно сохраняет текущую версию рядом с исходником, с суффиксом `.before-restore-<uuid>`. При восстановлении остановите воспроизведение и другие программы, меняющие этот файл. После восстановления нажмите **Обновить**. Можно также вручную скопировать файл из `backup` в `original`, указанные в журнале; `restore.json` сам по себе аудиоданных не содержит.

## Форматы и ограничения

| Возможность | MP3 | FLAC | OGG Vorbis |
|---|---|---|---|
| Основные теги, исполнитель альбома, комментарий | Да | Да | Да |
| Обычный текст песни: вручную / выбранный результат LRCLIB | Да | Да | Да |
| Обложка JPEG / PNG | Да, ID3v2 APIC | Да, PICTURE | Да, METADATA_BLOCK_PICTURE |
| Неизменённые дополнительные теги | Сохраняются через TagLib | Сохраняются через TagLib | Сохраняются через TagLib |

- Не поддерживаются Ogg Opus, WAV, MP4/M4A, запись синхронизированного LRC/SYLT, аудиоотпечатки и акустическое сравнение. Файл Opus с расширением `.ogg` отображается как ошибка.
- Редактируемые поля: `TITLE`, `ARTIST`, `ALBUM`, `ALBUMARTIST`, `TRACKNUMBER`, `DISCNUMBER`, `DATE`, `GENRE`, `COMMENT`, `LYRICS`. Поле даты допускает дату, а не только год; конкретное представление зависит от TagLib и формата. Неподдержанный результат не выдаётся за успешный: сохранённые значения проверяются.
- Многозначные теги показываются через `; `. Пока поле не изменено, исходный список сохраняется. При редактировании оно становится одним значением; отдельного редактора списков в этой версии нет.
- Все распознанные текстовые поля доступны для просмотра. Для нераспознанных и сложных полей показаны идентификаторы; бинарные данные не редактируются. Приложение не вызывает удаление неизвестных тегов. Полная резервная копия сохраняет исходное представление даже при ограничениях TagLib.
- В редакторе отображается первая обложка и число обложек. Замена/удаление явно относится ко **всем** обложкам файла; при обычном редактировании текста обложки не меняются. Входящие изображения ограничены 20 МБ. Во время массового сканирования обложки не сохраняются в модели, чтобы не занимать гигабайты памяти.
- Названия файлов, структура папок и звуковой поток при редактировании тегов не меняются. Сама область метаданных может быть пересобрана библиотекой.
- Совпадения повторов эвристические; возможны пропуски при разных названиях или большой разнице длительности. Высокий битрейт не доказывает лучшее качество источника.
- Версия 0.2 не содержит установщика, автоматической очистки копий и истории с кнопкой отката. Закрытие во время задачи требует отменить её и дождаться завершения текущего файла.

## Выбор издания и альбомные теги

После выбора найденной записи MusicBrainz загружается страница **связанных с её MBID изданий**, а не альбом с похожим названием. Таблица показывает альбом, исполнителя альбома, дату, тип и статус издания, страну, носитель, номер диска и трека, уточнение и MBID. Поля без данных показываются как `—` и не предлагаются для записи.

- Ни первая запись, ни первое издание не выбираются автоматически. Метка сильного совпадения — только подсказка.
- Кнопка **Ещё издания** получает следующую страницу. Смещение увеличивается на фактическое число полученных изданий: MusicBrainz может сокращать страницу по числу треков.
- Номер трека извлекается только из вхождения выбранного recording MBID в треклист. Если одна запись встречается на нескольких дисках или позициях одного издания, в таблице будут отдельные строки. Если треклиста нет, номер не выдумывается.
- **Без альбома и обложки** снимает выбор издания. Кнопка **В предпросмотр** остаётся доступной для одних `TITLE` и `ARTIST`, в том числе при ошибке загрузки изданий.
- Выбор издания предлагает только известные `ALBUM`, `ALBUMARTIST`, `DATE`, `TRACKNUMBER`, `DISCNUMBER`. Тип/статус/страна служат для сравнения, в отдельные теги не записываются. Исполнитель альбома берётся из album artist credit, а не копируется из исполнителя записи.

## Автоматическое предложение обложки

При выборе строки издания приложение автоматически запрашивает **его лицевую обложку** через `https://coverartarchive.org/release/<release-mbid>/front`. Подстановки обложки release-group или другого издания нет. Смена строки сбрасывает предыдущее предложение и отменяет его запрос; запоздалый ответ не может заменить картинку нового издания.

Показываются миниатюра, источник с MBID, размер изображения и кнопка **Открыть полный размер** (масштаб 100%, прокрутка). Это та же картинка, которая может быть записана, а не отдельная миниатюра другого размера. Если обложка отсутствует (HTTP 404), повреждена, неподдерживаемая или загрузка завершилась ошибкой, предложение обложки не создаётся. Текущие обложки остаются без изменений.

В общем предпросмотре обложка имеет отдельный флажок и миниатюры «сейчас → предложение». При наличии старой картинки явно написано **ЗАМЕНА ВСЕХ существующих обложек**. Двойной щелчок открывает полный размер; по столбцу «Сейчас» — текущую картинку, по «Предложение» — новую. Можно выбрать только картинку, только часть альбомных тегов или любое сочетание. Все флажки изначально сняты. Источник переносится в итоговый список изменений.

Ограничения сетевой картинки: 20 МиБ, JPEG/PNG, максимум 25 мегапикселей и 10000 пикселей по стороне. Лимит проверяется по заголовку и по фактически полученным байтам; перед предложением изображение декодируется и проверяется. Не реализован выбор задней обложки, буклета и нескольких картинок CAA. Нет автоматического удаления или подмены текущей обложки при отсутствии результата.

## Необязательный поиск текста одного трека

Выделите **ровно один** файл и нажмите **Текст песни**. Само открытие окна не обращается к сети. Проверьте или уточните название, исполнителя и необязательный альбом, затем нажмите **Найти в LRCLIB**. Исправление поисковых полей само по себе теги файла не меняет.

LRCLIB возвращает кандидатов. В окне видны источник и ID, название, исполнитель, альбом, длительность, тип текста, причины сравнения и полный текст. Ничего не выбирается автоматически. Для допуска к предпросмотру требуются совпадение названия и исполнителя, известная длительность с отклонением до 2 секунд, отсутствие конфликта альбома (если он указан) и обнаруженных признаков версии. Если остаётся несколько подходящих записей, добавление блокируется: уточните альбом. Одного совпадения названия недостаточно; точность данных сервиса всё равно требует ручной проверки.

Обычный текст добавляется отдельным полем `LYRICS` в существующий процесс предпросмотра и подтверждения. При ошибке сервиса, пустом результате, instrumental-записи, несовпадении или неоднозначности ничего не предлагается к записи. Изменение поисковых полей очищает старые результаты.

**Синхронизированный LRC** явно помечен и показывается с временными метками, но доступен только для просмотра: запись SYLT и форматированных LRC-тегов в этом этапе не реализована. Временные метки не удаляются с выдачей результата за обычный текст. Если LRCLIB возвращает и обычную, и синхронизированную версии, это отдельные строки; выбрать для записи можно только обычную. Другие форматы `lyricsfile` / пословная синхронизация не импортируются. Поиск LRCLIB ограничен возможностями API (до 20 результатов, без пагинации). Массового поиска текстов нет.

## Сервисы, отправляемые данные и кэш

| Действие | Сервис | Что передаётся |
|---|---|---|
| Поиск записи | MusicBrainz | Название и исполнитель из тегов и/или имён файла и папки |
| Просмотр изданий | MusicBrainz | MBID выбранной записи, смещение страницы |
| Предложение обложки | Cover Art Archive / Internet Archive при перенаправлении | MBID выбранного издания, запрос лицевой обложки |
| Явный поиск текста | LRCLIB | Введённые название, исполнитель, непустой альбом |

Длительность сравнивается локально. Сервисы видят IP и User-Agent приложения. **Аудиофайлы, полные локальные пути, существующие обложки и существующие тексты не загружаются.** Функции отправки аудио в этой версии нет. API-ключи для этих публичных GET-запросов не нужны. [Документация LRCLIB](https://lrclib.net/docs) открывает API для приложений, требует идентификацию клиента и соблюдение `Retry-After`; приложение использует только чтение, без публикации текстов.

Общая последовательная очередь выдерживает минимум 1,1 секунды между запросами к одному хосту. Таймаут отсутствия передачи данных — 20 секунд, не более пяти перенаправлений; переход HTTPS → HTTP не разрешён. HTTP 429/503 учитывает `Retry-After` (число секунд или HTTP-дата); без корректного значения вводится пауза 60 секунд. Автоматической повторной отправки неудачного запроса нет: действие можно повторить вручную. JSON ограничен 4 МиБ. Успешные ответы и проверенные изображения кэшируются 30 дней в `QStandardPaths::CacheLocation/online-v2`. Ошибки не кэшируются; повреждённая запись кэша отбрасывается. Старый кэш `musicbrainz` версии 0.1 не используется. Общий размер дискового кэша пока не ограничен; его можно очистить вручную.

User-Agent: `MusicOrder/0.2.0 (https://github.com/SweeetDozer/nmm)`. Для собственного форка замените контакт в коде или настройку `musicbrainz/contact` в QSettings. Интерфейс `MetadataSource` сохранён; сетевой транспорт общий для поиска записей, изданий, картинок и текстов.

Документация протоколов: [MusicBrainz — очередь запросов](https://musicbrainz.org/doc/MusicBrainz_API/Rate_Limiting), [MusicBrainz — browse и пагинация](https://musicbrainz.org/doc/MusicBrainz_API), [Cover Art Archive](https://musicbrainz.org/doc/Cover_Art_Archive/API), [LRCLIB](https://lrclib.net/docs), [сложные поля TagLib](https://taglib.org/api/classTagLib_1_1FileRef.html).

## Проверки без настоящей фонотеки

```bash
sudo dnf install python3 ffmpeg-free
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug -DBUILD_TESTING=ON
cmake --build build -j 4
ctest --test-dir build --output-on-failure
```

FFmpeg должен иметь кодировщики `libmp3lame`, `flac`, `libvorbis` (проверить: `ffmpeg -encoders`). Это зависимость тестовых генераторов, не редактора.

Тесты создают временные синусоидальные MP3/FLAC/OGG, проверяют запись всех основных полей, Unicode, обложки, их удаление, сохранение дополнительных тегов, хеш резервной копии, отклонение устаревшего предпросмотра, перенос и восстановление. FFmpeg сравнивает SHA-256 декодированного звука до и после операций. Отдельно проверяются консервативность предложений и отсутствие выдуманного альбома. UI-тест создаёт 5000 коротких файлов и один повреждённый: проверяет сканирование, работу цикла событий, фильтры, поиск, сортировку и отмену. Данные из пользовательской коллекции не используются. Обычный CTest не обращается в интернет: новый `online_choices` поднимает локальный HTTP-сервер с подставными ответами и временным кэшем. Он проверяет выбор второго издания вместо первого, номера дисков и пагинацию, отсутствие альбомного выбора по умолчанию, защиту от картинки другого издания и устаревших ответов, HTTP 404/500, повреждённое изображение, лимит загрузки, кэш, отмену, явный запуск поиска текста, неоднозначность и запрет записи LRC. Тесты TagLib отдельно проверяют альбомные поля при сохранении обложки, замену только обложки без изменения текстовых тегов и запись только текста без изменения альбома и обложки.

При желании отдельно проверить настоящий запрос к MusicBrainz на общедоступной записи (нужен интернет):

```bash
MUSICORDER_LIVE_TEST=1 ./build/search_test liveService
```

Этот запрос отдельно проверен при разработке; пользовательские аудиофайлы для него не нужны.

## Путь к Windows

Код не использует POSIX-функции для работы с файлами. Пути Windows передаются в TagLib как UTF-16, операции и потоки реализованы через Qt. Сборка Windows в этой среде **не проверена**; готового Windows-дистрибутива пока нет.

Вариант сборки: Visual Studio 2022 с поддержкой C++20, CMake, Qt 6 с компонентом Multimedia и TagLib ≥ 2.0 той же архитектуры/ABI. TagLib предоставляет CMake target `TagLib::TagLib`; pkg-config не нужен.

В Developer PowerShell, указав фактические пути установленных библиотек:

```powershell
cmake -S . -B build-win -DCMAKE_PREFIX_PATH="C:/Qt/6.x/msvc2022_64;C:/deps/taglib" -DBUILD_TESTING=OFF
cmake --build build-win --config Release
C:/Qt/6.x/msvc2022_64/bin/windeployqt.exe build-win/Release/musicorder.exe
```

В дистрибутив также нужны DLL TagLib и её зависимостей, необходимые плагины/кодеки Qt Multimedia. Следующий этап упаковки — CI на Windows, проверка Unicode-путей и кодеков, затем установщик. Не смешивайте MSVC- и MinGW-библиотеки.

## Структура

- `src/core.*`: чтение, точечная запись, проверка, копии, перенос.
- `src/window.*`: модель/фильтр таблицы, фоновые задачи, редактор, пакетный предпросмотр, повторы.
- `src/search.*`: интерфейс источников, поиск записей MusicBrainz, оценка совпадений.
- `src/http.*`: общая ограниченная очередь, кэш, проверка загрузок и отмена.
- `src/online.*`: связанные издания, привязка обложки к релизу, консервативный отбор текста LRCLIB.
- `src/online_dialogs.*`: отдельные окна ручного выбора записи/издания и текста.
- `scripts/restore.py`: восстановление по журналу с проверкой копии.
- `tests/`: воспроизводимые проверки на синтетических данных.
